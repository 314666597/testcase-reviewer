# 通用测试用例评审标准

## 1. 评审目的

*   **发现缺陷**：找出用例中逻辑错误、场景遗漏、预期结果不准确等问题。
*   **统一认知**：确保产品、开发、测试三方对需求理解一致，避免认知偏差。
*   **提升质量**：确保用例覆盖度、深度及可执行性达到发布标准。
*   **风险识别与建议**：识别性能、兼容性、第三方依赖等潜在风险，并提供专项测试建议，明确测试边界。

---

## 2. 评审指标体系（7大维度）

### 维度一：覆盖率（核心场景）

| 评审项 | 检查要点 | 常见遗漏 |
| :--- | :--- | :--- |
| **需求覆盖** | 是否覆盖PRD中的所有功能点、业务规则、隐式需求？ | 遗漏非功能需求、隐式规则 |
| **正向场景** | 核心业务流程是否完整覆盖？ | 遗漏核心链路的分支场景 |
| **功能回归** | 是否识别了新需求对已有功能的影响？ | 完全未提及相关功能的回归测试 |

### 维度二：准确性与一致性

| 评审项 | 检查要点 | 常见遗漏 |
| :--- | :--- | :--- |
| **需求对齐** | 用例是否与最新的PRD、原型图、UI设计稿一致？ | 需求变更后用例未同步更新 |
| **预期结果** | 预期结果是否明确、可量化、无歧义？ | 使用“系统正常”“操作成功”等模糊描述 |
| **术语统一** | 用例术语是否与项目字典、产品文档一致？ | 同一概念使用不同术语（如“登录/登陆”） |

### 维度三：可执行性&可维护性

| 评审项 | 检查要点 | 常见遗漏 |
| :--- | :--- | :--- |
| **前置条件** | 是否清晰描述执行用例前必须满足的状态？前置条件是否可复现？ | 前置条件缺失或不可复现 |
| **步骤清晰** | 测试步骤是否逻辑连贯、无跳跃？他人能否无歧义执行？ | 步骤跳跃，依赖隐含前提 |
| **优先级明确** | 是否标注优先级（P0/P1/P2/P3）？优先级定义是否合理？ | 全P0或优先级混乱 |

**优先级定义标准**：
- **P0（冒烟测试）**：核心业务流程，阻塞性问题，必须通过后方可继续测试。
- **P1（高优先级）**：重要功能，主要业务规则，影响用户体验。
- **P2（中优先级）**：边界条件、次要异常场景、次要功能。
- **P3（低优先级）**：建议执行、易用性、极低频场景。

### 维度四：基础安全校验（必须覆盖）

> **评审原则**：本维度为**必须覆盖项**，用例缺失将直接影响评审结论。旨在确保应用基础的安全防护能力，防止因权限绕过或数据泄露引发安全风险。

| 评审项 | 检查要点 | 常见遗漏 |
| :--- | :--- | :--- |
| **权限控制** | **水平越权**：用户A是否能访问或操作用户B的数据？<br>**垂直越权**：普通用户是否能执行管理员操作？<br>**未授权访问**：未登录用户是否能访问需鉴权的接口或页面？ | 只验证有权限的正常场景，完全遗漏各类越权场景的校验。 |
| **敏感信息** | **数据展示**：敏感数据（手机号、身份证、银行卡、邮箱等）在页面和接口响应中是否按要求脱敏？<br>**日志打印**：密码、Token、身份证等敏感信息是否在日志中明文打印？<br>**前端源码**：敏感信息是否未硬编码在HTML/JS中？ | 仅验证功能正常，未验证敏感信息的展示和存储安全。 |

### 维度五：核心异常场景覆盖（必须覆盖）

> **评审原则**：本维度为**必须覆盖项**，用例缺失将直接影响评审结论。大量线上P0故障源于此类异常场景遗漏，包括系统容错、并发控制、幂等性、数据一致性等核心稳定性问题。

| 评审项 | 检查要点 | 常见遗漏 |
| :--- | :--- | :--- |
| **系统异常** | **接口500/502/503**：服务端返回5xx错误时，前端/客户端是否有合理提示？是否记录错误日志？<br>**接口超时**：请求超时后是否有重试机制？重试策略是否合理（次数、间隔）？超时后用户看到什么？ | 只验证接口正常返回，完全遗漏异常状态码的验证；未考虑超时后的重试导致的数据重复问题。 |
| **并发与幂等** | **并发冲突**：多人同时操作同一资源（如编辑同一条数据、抢购同一商品），系统如何处理？是否有乐观锁/悲观锁机制？<br>**重复提交**：用户快速点击两次提交按钮，是否会生成两条重复数据？前端是否防抖？后端是否幂等？<br>**幂等性**：同一请求重复发送（如网络重试、回调重复），系统是否能保证结果一致？ | 只验证单用户单次操作，未覆盖并发冲突；未验证重复提交导致的脏数据；未验证回调重复处理的幂等性。 |
| **数据一致性** | **分布式事务**：跨多个服务/数据库的操作（如订单+库存+积分），部分失败时是否有回滚？数据是否一致？<br>**状态机异常**：数据状态流转过程中，是否允许非法状态变更？并发状态变更时是否会出现状态错乱？ | 只验证正常状态流转，未验证状态机边界和并发状态变更；未验证部分失败场景的数据一致性。 |

### 维度六：场景深度检查项（建议覆盖）

> **评审原则**：本维度内容旨在**提升用例深度和质量**，不作为用例评审“不通过”的判定依据。若用例未覆盖以下内容，评审意见中应作为“优化建议”提出。

| 评审项 | 检查要点 | 优化建议 |
| :--- | :--- | :--- |
| **边界值** | 有效等价类、无效等价类、边界值（最大/最小/空/特殊字符）是否覆盖？ | 若未覆盖，建议补充边界值和无效等价类用例，提升数据验证的完整性。 |
| **网络异常** | **断网**：操作过程中断网，是否有明确提示？恢复网络后状态是否正确？<br>**弱网**：弱网环境下加载是否超时？是否有合理的loading和超时提示？<br>**网络切换**：WiFi切4G、4G切WiFi时，请求是否中断？状态是否保留？ | 若未覆盖，建议补充网络异常场景用例，提升弱网环境下的用户体验。 |
| **UI一致性** | UI交互细节（加载态、空态、极限文本、不同分辨率下的布局）是否有覆盖？ | 若未覆盖，建议补充UI状态和极端数据展示用例，提升用户体验的细节质量。 |
| **非功能识别** | 是否识别了性能、兼容性等专项测试需求？ | 若未覆盖，建议评估是否需要专项测试，并补充相关标识。 |

### 维度七：风险识别与建议

> **评审原则**：本维度内容旨在**识别风险并提供优化建议**，不作为用例评审“不通过”的判定依据。

| 评审项 | 检查要点 | 优化建议 |
| :--- | :--- | :--- |
| **性能风险** | 是否识别了高并发、大数据量、响应时间敏感等性能需求？ | 若未覆盖，建议评估是否需要专项性能测试。 |
| **兼容性风险** | 是否识别了浏览器、设备、操作系统、分辨率等兼容性需求？ | 若未覆盖，建议明确兼容性测试范围。 |
| **第三方依赖风险** | 核心流程是否依赖第三方服务（支付、短信、地图等）？是否覆盖第三方异常场景？ | 若未覆盖，建议补充第三方服务不可用、超时、返回错误等场景用例。 |
| **业务安全** | 是否覆盖并发抢购超卖、价格篡改等业务逻辑安全？ | 若未覆盖，建议评估风险并补充对应的安全用例。 |

## 3. 评审检查清单（Checklist）

### 3.1 通用检查项 (必检)

- [ ] **需求覆盖**：所有需求条目均有对应用例（正向+反向）。
- [ ] **正向场景**：核心业务流程完整覆盖。
- [ ] **预期结果**：明确可量化，无歧义。
- [ ] **前置条件**：清晰、可复现。
- [ ] **步骤清晰**：逻辑连贯，无跳跃。
- [ ] **优先级**：P0用例无遗漏，且数量控制在合理范围（通常占总用例10%-20%）。
- [ ] **回归测试**：对本次变更相关的功能进行回归测试。
- [ ] **术语统一**：用例术语与项目文档一致。
- [ ] **需求对齐**：用例与最新PRD、原型图、UI设计稿一致。

### 3.2 基础安全校验项 (必检)

- [ ] **水平越权**：是否包含“用户A操作/查看用户B数据”的校验用例？
- [ ] **垂直越权**：是否包含“普通用户执行管理员操作”的校验用例？
- [ ] **未授权访问**：是否包含“未登录用户访问需登录页面/接口”的校验用例？
- [ ] **数据脱敏**：是否验证了敏感字段在页面和接口返回时的脱敏规则？
- [ ] **日志安全**：是否验证了敏感信息（密码、Token等）未在日志中明文打印？

### 3.3 核心异常场景覆盖项 (必检)

- [ ] **系统异常**：是否覆盖接口5xx错误、超时等场景？
- [ ] **并发冲突**：是否覆盖多人同时操作同一资源的场景？
- [ ] **重复提交**：是否覆盖快速连续点击、网络重试导致的重复提交场景？
- [ ] **幂等性**：是否验证同一请求重复发送时的结果一致性？
- [ ] **数据一致性**：是否覆盖分布式事务部分失败、状态机非法变更等场景？

### 3.4 场景深度检查项 (建议项)

- [ ] **边界值**：是否覆盖了有效/无效等价类、边界值（最大/最小/空/特殊字符）？
- [ ] **网络异常**：是否覆盖了断网、弱网、网络切换等场景？
- [ ] **UI一致性**：是否覆盖了加载态、空态、极限文本等UI细节？
- [ ] **非功能识别**：是否识别了性能、兼容性等专项测试需求？

### 3.5 风险识别与建议项 (建议项)

- [ ] **性能风险**：是否识别了高并发、大数据量等性能风险？
- [ ] **兼容性风险**：是否明确了兼容性测试范围？
- [ ] **第三方依赖**：是否识别了第三方服务依赖及异常场景？
- [ ] **业务安全**：是否覆盖价格篡改等业务安全场景？

## 4. 评审提问模板

### 通用提问
> “这个功能的核心业务场景是什么？对应的P0用例是否完整？”

### 基础安全校验提问（必问）
> “这个功能涉及哪些用户角色和数据？**必须确认**是否已覆盖水平越权、垂直越权、未授权访问的用例？”
> “这个功能涉及哪些敏感信息？**必须确认**是否已覆盖页面脱敏、接口脱敏、日志不打印明文的验证用例？”

### 核心异常场景覆盖提问（必问）
> “这个功能涉及的接口，如果返回500错误或超时，**必须确认**是否有对应的用例？前端如何处理？是否记录日志？”
> “这个功能是否有并发风险？**必须确认**是否覆盖多人同时操作同一资源的场景？系统如何处理冲突？”
> “这个功能是否存在重复提交风险？**必须确认**是否覆盖快速点击、网络重试导致重复提交的场景？后端是否保证幂等？”
> “这个功能涉及跨服务操作（如订单+库存）吗？**必须确认**是否覆盖部分失败时的数据一致性验证？状态机是否有非法变更的校验？”

### 场景深度建议提问
> “**建议**评估是否需要补充边界值用例，增强数据验证的健壮性。”
> “**建议**评估是否需要补充网络异常用例（断网/弱网/网络切换），提升弱网环境下的用户体验。”
> “**建议**评估是否需要补充UI细节用例，提升用户体验完整性。”

### 风险识别与建议提问
> “这个功能是否存在性能风险？**建议**考虑是否需要专项性能测试。”
> “核心流程是否依赖第三方服务？**建议**考虑补充第三方异常场景和降级方案用例。”

### 回归提问
> “这次改动影响哪些上下游模块？是否需要回归核心流程？”

## 5. 评审结论标准

| 结论 | 标准 | 后续动作 |
| :--- | :--- | :--- |
| **通过** | 无P0/P1级缺陷，核心场景覆盖达标，表述清晰。**基础安全校验项（权限控制、敏感信息）完整覆盖。核心异常场景覆盖项（系统异常、并发与幂等、数据一致性）完整覆盖。** 场景深度项及风险识别项缺失不作为否决条件。 | 允许基线化，进入测试执行阶段。 |
| **有条件通过** | 存在少量P2/P3级缺陷（如描述不清晰、冗余），不影响核心执行。**基础安全校验项和核心异常场景覆盖项必须完整覆盖。** 场景深度项及风险识别项的缺失不在此列。 | 修改后由评审组长复核，无需二次全员会议。 |
| **不通过** | 存在P0/P1级缺陷（核心场景遗漏、预期结果错误、前置条件缺失严重等）。**或基础安全校验项存在任一遗漏。或核心异常场景覆盖项存在任一遗漏（接口500/超时、并发冲突、重复提交、幂等性、数据一致性等）。** | 修改后重新发起正式评审。 |

## 6. 常见评审问题示例（红线对照）

| 问题类型 | ❌ 坏示例 | ✅ 好示例 |
| :--- | :--- | :--- |
| **接口异常遗漏** | 只验证“接口返回200，数据正常展示” | **（必须覆盖）** 补充“接口返回500时，页面提示‘系统繁忙，请稍后重试’，控制台记录错误日志”“接口超时3秒后，显示超时提示，支持手动重试” |
| **并发冲突遗漏** | 只验证“单用户修改订单状态成功” | **（必须覆盖）** 补充“A用户和B用户同时编辑同一订单，后提交者收到‘数据已被修改，请刷新后重试’提示，数据不被覆盖” |
| **重复提交遗漏** | 只验证“点击提交按钮，订单生成成功” | **（必须覆盖）** 补充“快速连续点击提交按钮10次，只生成1笔订单”“网络重试导致同一请求发送2次，后端通过唯一键/幂等token保证不重复处理” |
| **幂等问题遗漏** | 只验证“支付回调正常处理” | **（必须覆盖）** 补充“支付回调重复发送3次，订单状态只更新一次，账户只入账一次，幂等性验证通过” |
| **分布式事务遗漏** | 只验证“下单扣库存加积分均成功” | **（必须覆盖）** 补充“下单成功但扣库存失败，订单状态回滚为失败，积分不增加”“扣库存成功但加积分失败，是否有补偿机制？数据最终一致？” |
| **状态机异常遗漏** | 只验证“订单从待支付变为已支付” | **（必须覆盖）** 补充“已支付的订单尝试再次支付，系统提示‘订单已支付’”“已取消的订单尝试支付，系统提示‘订单已失效’” |
| **越权遗漏** | 只验证“管理员可删除用户” | **（必须覆盖）** 补充“普通用户尝试删除其他用户”“普通用户尝试删除管理员”等越权用例 |
| **敏感信息遗漏** | 未验证敏感数据展示 | **（必须覆盖）** 补充“手机号页面展示为188****1234，接口返回同样脱敏；日志中确认不打印密码明文” |
| **网络异常遗漏** | 只测“正常网络下提交订单” | **（建议）** 建议补充“提交订单时断网，提示‘网络连接失败’；恢复网络后，订单状态同步正确”“弱网环境下，loading超时后提示重试” |
| **边界值遗漏** | 只测“输入金额100元” | **（建议）** 建议补充“金额为0、负数、最大限额、小数位数超限”等边界值用例 |
| **UI一致性遗漏** | 只测“列表有数据时的展示” | **（建议）** 建议补充“列表为空时的空态页、加载中的loading动画”等UI细节用例 |
